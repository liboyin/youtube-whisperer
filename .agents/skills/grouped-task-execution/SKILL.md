# Grouped Task Execution

This repository-local skill records the user's recommended workflow. [AGENTS.md](../../../AGENTS.md) owns working standards, [TODO.md](../../../TODO.md) owns task boundaries and maintenance, and the [adversarial review skill](../adversarial-review/SKILL.md) owns review mechanics. Follow those documents without duplicating their procedures. Explicit user instructions take precedence over this recommendation.

1. **Select and bound the group.** Find a small, high-value group of closely coupled TODO tasks sharing a behavior, invariant, or dependency. Revalidate them against current code and expand each task into its own execution boundary under TODO's rules. Preserve the accepted boundaries in the [review evidence record](../adversarial-review/SKILL.md#evidence-retention) before completed entries are removed from TODO, so they remain available for final review and handoff. Grouping tasks does not expand their authorized scope or settle unresolved material decisions.
2. **Order and delegate.** Implement foundations before dependent behavior. Assign each task to its own GPT-6 Sol subagent (`model: "gpt-6.1-sol"`), using `fork_turns: "none"` with an explicit assignment so the model override is supported. Supply the task boundary, dependencies, repository path, relevant documentation, and unrelated work to preserve. Execute dependent tasks sequentially, making validated prerequisite changes available before dispatching the next task. Parallelize only independent work with compatible edit and validation boundaries. The main agent owns integration and verification.
3. **Integrate and choose commit boundaries.** Keep functionally independent changes in separate self-contained commits, each with its own required gates and pre-commit review. Tightly coupled tasks delivered together MAY form one cohesive commit with one integrated review. Choose that boundary before committing; grouping does not waive review of a separately committed candidate. The main agent owns final validation, review dispatch, dispositions and commits. Maintain TODO under its own rules.
4. **Review what has not been covered.** For a combined candidate, review all accepted boundaries, acceptance criteria, retained behavior and integration paths before commit. For already reviewed tasks, assess whether integration introduces behavior or risks their reviews did not cover; record the coverage decision and obtain a further group review only when needed. Use the [review skill](../adversarial-review/SKILL.md#review-scope) for scope, reviewer continuity and follow-ups. A full integrated review reassesses earlier conclusions against the combined behavior.
5. **Close the group.** Disposition findings under AGENTS and the review skill. After non-trivial fixes, repeat required gates and obtain an updated verdict. Finish when done criteria are met, no Blocking finding remains, and every finding has a disposition. Report changes, checks, review verdict, deferrals and limitations, and link the retained review record. Clean up disposable artifacts under the skill's [retention rules](../adversarial-review/SKILL.md#evidence-retention).
