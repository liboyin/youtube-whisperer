# NB44 — The Azure worker checks for an existing WAV itself

## Origin

The [D48](../DESIGN.md#d48) gap review (2026-10-23) proposed this simplification. `AzureWorker.dispatch_task` checked `wav_source.is_file()` before calling `save_as_wav_file(..., NEVER)`, and raised `RuntimeError` when that call returned `None`. That call already keeps an existing WAV, and returns `None` for exactly that case.

The user decided [D49](../DESIGN.md#d49) (3) on 2026-10-23: drop the worker's own check. They accepted that the source must then exist even when its WAV does.

## Boundary

- **Intent:** for every non-WAV source, call `save_as_wav_file(source, output_file_path=<sidecar>, overwrite=NEVER)` and transcribe the sidecar path.
- **Compatibility surface:** `AzureWorker.dispatch_task`.
  - The source must exist even when its WAV does; otherwise input validation raises before Azure and the task is dead-lettered as before.
  - Reuse now prints the library's "Not overwriting path" message.
  - WAV input is unchanged.
- **Non-goals:** changes to `save_as_wav_file`.

## Change

- **Worker:** [azure_worker.py](../youtube_whisperer/workers/azure_worker.py) drops the existence check and the `RuntimeError` branch, and its docstring describes the reuse.
- **DESIGN:** the Azure WAV paragraph says the same.
- **Tests:**
  - `test_dispatch_task_reuses_existing_sidecar_wav` now runs the real `save_as_wav_file` with a test-owned source and existing WAV, and asserts that the WAV is unchanged and transcribed.
  - The `RuntimeError` test became `test_dispatch_task_transcribes_sidecar_when_conversion_keeps_existing_wav`.
  - `test_dispatch_task_requires_source_even_when_sidecar_wav_exists` was added for review finding R1.
