# NB11 — Authorized video overwrites replace atomically without losing the previous video

**Origin:** TODO recorded that `download_video` checked overwrite permission but never configured yt-dlp to overwrite, and yt-dlp keeps an existing final file by default. As a result, `ALWAYS` did not replace an existing video. NB11 was executed together with [NB8](NB8.md) as one cohesive change; the shared decisions, validation, mutation evidence and review are recorded there.

**Revalidation:** installed yt-dlp 2026.08.19 was inspected at `e3648cc`, and the inputs were unchanged at `81b99de`. `YoutubeDL.existing_file` keeps the existing file unless `overwrites` is set. With `overwrites: True` it deletes the existing file *before* the download starts, so simply forwarding the flag would lose the previous video when a replacement download failed. The user therefore chose a staged download with atomic publication ([decision](NB8.md)).

**Boundary:** the shared group constraints are in [NB8](NB8.md).

- **NB11 acceptance:**
  - `ALWAYS`, or an approved `PROMPT`, replaces an existing video and preserves its mode bits.
  - `NEVER`/`RENAME` with an existing file return without constructing yt-dlp.
  - Under `NEVER`, a competing regular file that appears during the download is kept. A competing directory or dangling symlink raises `FileExistsError`.
  - A failed or interrupted `ALWAYS` download leaves the previous video byte-identical.
  - A download that produces no regular staged file raises without publishing.
  - No stage directory remains on any path.
- **Verification constraint:** tests must use owned files and a downloader double that writes where real yt-dlp template evaluation directs. Mocking the entire download does not count.

**Change:** the preflight consent check is unchanged. After the download and context exit succeed, the regular staged file receives the previous mode bits, if a file existed, and is published:

- **`NEVER`/`RENAME`:** `os.link` create-if-absent. The call returns only when the collision is a regular file, or a symlink to one; any other collision propagates.
- **All other modes:** `os.replace`, following the resolved symlink target.

Because each download starts in a fresh, empty stage, yt-dlp never sees an existing final file or a stale `.part` to resume, so its `overwrites` flag is not needed. The stage directory is always removed. [DESIGN](../DESIGN.md#srt-as-the-output-format) now states that video, SRT and WAV publication share the completion contract, and [D22](../DESIGN.md#d22) covers video.
