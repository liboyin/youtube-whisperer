# NB42 — The overwrite-policy check admits values other than ALWAYS and NEVER

## Origin

The [D48](../DESIGN.md#d48) gap review (2026-10-23) found that `require_supported_policy` rejected only `OverwritePolicy.RENAME`. pathlib-extensions `fff2bf6` publishes `ALWAYS` and `NEVER` by identity and sends every other value down its numbered `RENAME` path. So `publish_srt_text` given `OverwriteMode.ALWAYS`, `OverwriteMode.NEVER` or the string `"always"` wrote `Title [id].1.srt` beside an existing SRT, the MP4/SRT pairing break that D48 bans `RENAME` to prevent. Other entry points failed later with `AttributeError`, and the default-title wrappers only after their metadata request. `save_as_wav_file` also validated its input before the policy (gap-review nit N4).

The user decided [D49](../DESIGN.md#d49) (1) on 2026-10-23: use an allowlist, superseding [NB38](NB38.md)'s accepted absence of a runtime check.

## Boundary

- **Intent:** accept only the `OverwritePolicy.ALWAYS` and `NEVER` members, by identity. Equality would not do, because `OverwriteMode.ALWAYS == OverwritePolicy.ALWAYS` and `"always" == OverwritePolicy.ALWAYS`. Everything else raises `ValueError` naming the value.
- **WAV:** `save_as_wav_file` checks the policy before its input.
- **Compatibility surface:** every function taking `overwrite`.
  - Valid policies are unaffected.
  - Other values now raise `ValueError` before any work. The message changed from `OverwritePolicy.RENAME is not supported: use ALWAYS or NEVER` to `Overwrite policy <repr> is not supported: use OverwritePolicy.ALWAYS or NEVER`.
- **Non-goals:** a `Literal` type alias.

## Change

- **Helper:** [overwrite.py](../youtube_whisperer/overwrite.py) implements the identity allowlist and documents why.
- **WAV:** [waveform_loader.py](../youtube_whisperer/transcriber/waveform_loader.py) calls `require_supported_policy` first.
- **Docstrings:** six source modules now say `ValueError: If overwrite is not ALWAYS or NEVER`.
- **DESIGN:** the completion-contract paragraph names stale `OverwriteMode` members and strings among the refused values.
- **New tests:**
  - helper rejection of `OverwriteMode.ALWAYS`, `OverwriteMode.NEVER`, `"always"`, `"never"` and `None`;
  - `publish_srt_text` with a stale value leaves the existing SRT as the only file;
  - WAV with a missing input and `RENAME` raises the policy error.
- **Changed tests:** existing `RENAME` tests match the new message.
