# NB43 — The SRT helpers' defaults disagree, and in-place deduplication does nothing by default

## Origin

After [D48](../DESIGN.md#d48), `publish_srt_text` defaulted to `ALWAYS`, while `save_segments_as_srt` and `deduplicate_srt_file` defaulted to `NEVER`. So `deduplicate_srt_file(p)` found its own input already present, printed "Not overwriting path" and returned without deduplicating. The D48 gap review (2026-10-23) reported this, and also that DESIGN's completion-contract paragraph said every public function defaults to `NEVER` (gap-review nit N1).

The user decided [D49](../DESIGN.md#d49) (2) on 2026-10-23: unify `srt_deduplicator.py` on `ALWAYS`.

## Boundary

- **Intent:** `save_segments_as_srt` and `deduplicate_srt_file` default to `ALWAYS`, and their docstrings and DESIGN say so.
- **Compatibility surface:** those two D18 defaults change. Explicit callers are unaffected, including both transcribers and caption publication, which pass their policies.
- **Non-goals:** defaults outside `srt_deduplicator.py`.

## Change

- **Source:** [srt_deduplicator.py](../youtube_whisperer/adaptors/srt_deduplicator.py) changes both defaults, and the three SRT helpers' docstrings say they share the `ALWAYS` default.
- **DESIGN:** the completion-contract paragraph now states the actual defaults: the SRT helpers use `ALWAYS`, `download_video` has none, and every other public function with an overwrite parameter uses `NEVER`.
- **Tests:**
  - The default case of `test_save_segments_as_srt_existing_output_policy_is_decided_before_lazy_work` now expects replacement.
  - New: `test_deduplicate_srt_file_deduplicates_in_place_by_default` uses its own test-owned file.
  - `test_deduplicate_srt_file_keeps_existing_output_without_reading_input` keeps only its explicit-`NEVER` case.
