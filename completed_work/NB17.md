# NB17 — Non-string language input fails ordinary validation

**Origin:** TODO recorded a Medium, validated finding: the plain validator behind `LanguageCode.__get_pydantic_core_schema__` raised `TypeError` for numeric, null or collection input. Pydantic v2 does not wrap `TypeError` from plain validators, so the error escaped model validation and the API's general exception handler answered `POST /tasks` with 500 instead of 422. Unsupported strings such as `fr` already produced a `ValidationError`.

**Boundary:** make non-string, non-`LanguageCode` language values fail ordinary Pydantic validation so that `POST /tasks` returns 422 and nothing is enqueued. Preserve the whitelist, registered strings and `LanguageCode` instances, unregistered and malformed string rejection, arrow rejection under [D23](../DESIGN.md#d23)/[D24](../DESIGN.md#d24), the strict constructor versus normalizing `from_str` difference, serialization and the JSON schema. Out of scope: whitelist changes, the generic 500 handler and worker handling of poison messages. Compatibility surface: HTTP malformed-language responses change from 500 to 422 as intended. Python callers validating a `Task` with a non-string language now receive `pydantic.ValidationError` (a `ValueError` subclass) instead of `TypeError`; this assumption follows from the task's 422 acceptance criterion. `LanguageCode(...)`, `from_str` and the other retained helpers are unchanged under [D18](../DESIGN.md#d18).

**Revalidation:** at `9d03f03` with Pydantic 2.13.5, `Task(source='x', language=v)` raised raw `TypeError` for `123`, `None`, `[]`, `{}`, `1.5` and `True`. Worker decoding (`workers/common.py::_decode_task`) and queue listing (`queueing.py`) catch neither `TypeError` nor `ValidationError` specifically, so the new exception type does not change worker routing.

**Change:** [lang_code_adaptor.py](../youtube_whisperer/adaptors/lang_code_adaptor.py) raises `ValueError("Unexpected language <repr> of type <name>")` for rejected non-string input. The validator parameter is annotated `object`, and both docstrings explain why it must raise `ValueError`. [test_models.py](../tests/test_models.py) replaces the test that protected the defect with a parametrized `ValidationError` test covering int, float, null, empty and non-empty lists, dicts and bools; it asserts the error is located only at `language`. [test_app.py](../tests/api/test_app.py) adds an HTTP test asserting 422 at `language` with neither queue function called. It uses `raise_server_exceptions=False` so a regression appears as a 500 response. [DESIGN HTTP contracts](../DESIGN.md#http-contracts) no longer lists NB17 as a known exception.
