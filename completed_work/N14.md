# N14 — Shell-tool gap-review follow-ups

## Origin

The main agent's gap review of the shell-helper group (`a4a1330..9ebe910`, 2026-10-12) did not use the adversarial-review skill. It found no defects and raised two Nits:

1. The three new test modules for [NB21](NB21.md), [N2](N2.md) and [NB20](NB20.md) each hand-rolled their bash subprocess harness. They differed in how they located bash, their missing-bash behavior, the `TMPDIR` layout, stdin handling and timeouts. A future copy could inherit the weakest variant.
2. README described `extract_subtitle_text.sh` only as stripping "SRT timestamps".

The user asked for an explanation of the first Nit, approved the shared-helper approach, and asked for the second Nit to be fixed. N14 was given an ID and closed in the same change, following [N13](N13.md).

## Boundary

- **Shared fixture:** a non-autouse fixture, `run_shell_script` in `tests/tooling/conftest.py`, owns the common harness. It:
  - resolves `bash` at invocation and asserts with a clear message if it is missing;
  - builds the environment from scratch: `PATH` is the caller's directories followed by `os.defpath`; `HOME` and `TMPDIR` are separate subdirectories of `tmp_path` that the runner exposes; `LC_ALL=C.UTF-8`; plus the caller's variables;
  - runs in `tmp_path` with stdin closed, captured output, `check=False` and one 30 s timeout;
  - returns text or bytes, as the caller selects.
- **Per-module choices kept:**
  - NB21 keeps bytes output.
  - NB20 keeps its stub, its invocation records, its extra `PATH` directories, its `COVERAGE_THRESHOLD` handling and its empty-`TMPDIR` assertion. Its import-time `bash`/`python3` assertion moved into the test path.
- **Compatibility surface:** test code and one README sentence only. The scripts, application code and coverage configuration are unchanged.
- **Non-goals:** new test cases and changes to `test_snapshot.py`.

## Review

A new Codex session made a full assessment of the N14 boundary: `01a1304b-c1f9-7843-a5b0-bbcadf7ef585`, model `gpt-6.1-sol`, reasoning effort `high`, both taken from the dispatch arguments. It found no Blocking findings, Non-blocking findings or Nits. The main agent's post-review snapshot matched the frozen pre-review snapshot exactly.

- **Mutants:** it reran all nine mutants and matched every outcome.
- **Probes:** it confirmed that the child does not inherit the parent's environment, including `BASH_ENV`, that a missing `bash` is diagnosed when the script is run, and that the fixture is not autouse.
- **stdin closure:** it showed the closure matters under `pytest -s`. With owned input on the parent's stdin, the child saw EOF, and removing `stdin=DEVNULL` failed a specific stdin assertion in that probe. Under pytest's default fd capture the closure cannot be distinguished, so no committed test protects it.

## Limitations and cleanup

No committed test pins the stdin closure, because the default capture mode already gives the child an empty stdin; it is a defensive setting carried over from NB21's harness. Scratch copies were deleted. Unrelated untracked files were preserved.
