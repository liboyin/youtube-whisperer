# NB38 — Overwrite policies still use OverwriteMode and PROMPT

## Origin

The user reshaped pathlib-extensions after `88aba06` and asked whether its new API suited this project. Commits `179d82b`..`fff2bf6` added `OverwritePolicy` (`ALWAYS`, `NEVER`, `RENAME`), rebuilt `publication.py` on it, and added `StagedFile`.

A scratch probe showed that the rebuilt `publish_staged_file` routes any value other than exactly `OverwritePolicy.ALWAYS` or `OverwritePolicy.NEVER` to its numbered `RENAME` path: `OverwriteMode.ALWAYS` and `OverwriteMode.NEVER` both published `x.1.txt`. The pin update and this migration therefore had to land together.

The user decided [D48](../DESIGN.md#d48) on 2026-10-22:

- `PROMPT` is removed, because a web app cannot ask for consent.
- Former `PROMPT` defaults become `NEVER`, with a hard break of [D18](../DESIGN.md#d18) for these parameters.
- `RENAME` is rejected, because numbered copies would break MP4/SRT pairing.
- `StagedFile` (NB39) and forwarder removal (NB40) follow as separate tasks.

During review the user added that backward compatibility need not be considered, so a runtime type check for non-policy values was unnecessary.

## Boundary

- **Intent:** pin pathlib-extensions `fff2bf6` and move every overwrite parameter to `OverwritePolicy`.
- **Direction:**
  - New [overwrite.py](../youtube_whisperer/overwrite.py):
    - `require_supported_policy` raises `ValueError` for `RENAME`.
    - `resolve_output_path` checks the policy and then calls `OverwritePolicy.resolve`.
  - The seven preflight sites use `resolve_output_path`: video download, `save_segments_as_srt`, `deduplicate_srt_file`, caption download, WAV conversion, Whisper and Azure.
  - `publish_srt_text` and the four public wrappers call `require_supported_policy` first. The wrappers are the default-title video and caption downloads, the playlist download and the combined download.
  - `resolve_publication_target` and `publish_staged_file` receive the policy.
- **Compatibility:**
  - Ten defaults change from `PROMPT` to `NEVER`, and `publish_srt_text` keeps `ALWAYS`.
  - In-place `deduplicate_srt_file` therefore needs an explicit `ALWAYS`.
  - A directory at the destination now fails at preflight, before downloads or transcription.
  - The printed messages are unchanged.
  - Workers keep `NEVER`.
- **Non-goals:**
  - `StagedFile` ([NB39](NB39.md));
  - forwarder removal ([NB40](NB40.md)).

## Limitations and cleanup

- **Containment deviation:** a quick K3 re-check was run by mutating the repository file in place instead of a scratch copy. It was restored at once, and the absence of mutant text was verified before the final gates.
