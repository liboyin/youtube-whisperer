# NB36 — Long titles containing dots fail filename truncation

## Origin

While surveying what could move to pathlib-extensions, the main agent probed the installed library at `3f39af6`:

- `truncate_filename(Path('/d') / ('Mr. Smith ' + 'x' * 300 + '.mp4'), 220)` raised `ValueError`, because everything after the first dot counted as the suffix.
- A 300-character name without a suffix returned `/d`, its parent directory.

Both default-title naming paths here call `truncate_filename(..., max_length=220)`, so such a video's download step should fail and be dead-lettered. That was not reproduced end to end.

## Boundary and change

[D46](../DESIGN.md#d46) settled the fix in pathlib-extensions: keep only the trailing run of extension-like suffixes. This project adopts it through the pin update shared with [NB37](NB37.md), which has the full boundary, library evidence, validation, review and limitations.

Two regression tests protect the adopted behavior: a 329-character title containing dots yields `title[:216] + '.mp4'` or `title[:216] + '.srt'` in the directory, and the derived path is passed on.

- `test_download_video_with_default_title_truncates_long_dotted_title_keeping_mp4_suffix`
- `test_download_as_srt_file_with_default_title_truncates_long_dotted_title_keeping_srt_suffix`

## Evidence

Reverting only the library's `filesystem.py` to `3f39af6` in the validation venv makes both tests fail with `ValueError: Not possible to truncate filename to fit in 220 bytes`. The Codex reviewer replayed this independently. Library-side mutation evidence and review are in [NB37](NB37.md#library-changes).

Gates, mutation evidence for the shared change, review and limitations: see [NB37](NB37.md#validation-and-provenance).
