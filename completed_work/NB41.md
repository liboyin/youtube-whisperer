# NB41 — SRT publication prepares its output without the overwrite policy

## Origin

The [D48](../DESIGN.md#d48) gap review (2026-10-23) found that `publish_srt_text` still called `prepare_output_file` before `StagedFile`. That check does not consider the overwrite policy, so it raised `PermissionError` when the process could not write a competing SRT that appeared during transcription, recognition or the caption fetch. Under `NEVER` that dead-letters a task even though valid output exists. `StagedFile` alone keeps such a competitor, because pathlib-extensions `fff2bf6` prepares a target it will keep without requiring write permission. The reviewer reproduced the failure with a probe at `27807b1`. Video, WAV and in-place deduplication repeated the same redundant preparation. The user authorized the fix.

## Boundary

- **Intent:** remove the four `prepare_output_file` calls that duplicate `StagedFile`'s policy-aware preparation:
  - `publish_srt_text`;
  - `deduplicate_srt_file`, with the type-narrowing assert after it, which mypy does not need;
  - `download_video`;
  - `save_as_wav_file`.
- **Retained:** the early call in `save_segments_as_srt`, which fails fast on an unwritable directory before Whisper's lazy decoding.
- **Compatibility surface:** the D18 functions `publish_srt_text`, `save_segments_as_srt`, `deduplicate_srt_file`, `download_video` and `save_as_wav_file` keep their signatures and results.
  - Under `NEVER`, a read-only competing file is now kept instead of raising.
  - An unwritable destination under `ALWAYS` still raises `PermissionError`, now from `StagedFile`.
  - Missing parents are still created, by `StagedFile`.
- **Non-goals:** other preparation or preflight calls.

## Change

- **Source:** [srt_deduplicator.py](../youtube_whisperer/adaptors/srt_deduplicator.py), [video_downloader.py](../youtube_whisperer/downloaders/video_downloader.py) and [waveform_loader.py](../youtube_whisperer/transcriber/waveform_loader.py) pass the caller's path straight to `StagedFile`. The video expanding-parent check now resolves the literal target path; resolution does not require the parent to exist.
- **New test:** `test_save_segments_as_srt_never_keeps_unwritable_competitor_created_during_work` creates a 0444 SRT while the blocks are consumed and asserts that it is kept unchanged with nothing else left behind. It is skipped for root, because root bypasses the permission check the race depends on.
- **Changed test:** the video early-return test now asserts that `StagedFile` is never constructed, replacing its mock of the removed `prepare_output_file`.
