# NB21 — Subtitle text extraction deletes valid dialogue and mishandles CRLF

## Origin

A 2026-09 assessment ([historical assessments](history.md#evidence-provenance)) used synthetic SRT shell reproductions and classified NB21 as Non-blocking, Medium severity, Validated. [extract_subtitle_text.sh](../extract_subtitle_text.sh) removed every digits-only line, so dialogue such as `2026` disappeared along with the cue indexes. It also removed every line containing `-->`. On CRLF input, the regular expressions saw the carriage returns, so indexes and blank lines survived. Acceptance required that numeric and ordinary dialogue, timestamps, indexes, blank lines, and equivalent LF and CRLF files produce the intended text.

NB21 was executed with [N2](N2.md) and [NB20](NB20.md) as a shell-helper group. The three tasks share one dependency: none of the repository's shell tools had tests. Each task was committed and reviewed separately.

## Boundary

The script must print every cue-text line and drop only SRT structure. LF and CRLF input must produce identical output.

- **Parsing rules:**
  - One trailing CR is stripped from every line, and a UTF-8 BOM from the first line.
  - A *timing line* matches `H+:MM:SS[,.]mmm --> H+:MM:SS[,.]mmm`, with whitespace around the arrow and optional trailing cue settings. Timing lines are dropped.
  - An *index* is a digits-only line immediately followed by a timing line. It is held for one line and printed if the next line is not a timing line, or at end of file.
  - Lines that are empty after stripping are dropped.
  - Every other line is printed unchanged, ending in LF.
- **Compatibility surface:** the CLI only, all of which is preserved:
  - the usage message and exit 1 for a wrong argument count;
  - output on stdout;
  - a non-zero exit for a missing or unreadable file;
  - the `find` usage comment.
- **Non-goals:** WebVTT, tag stripping, de-duplication, treating whitespace-only lines as blank, timestamp validation beyond the shape above, and a Python rewrite. The scripts stay bash with POSIX awk that runs under mawk 1.3.4.
- **Assumptions accepted by the main agent:**
  - The BOM is encoding structure, not dialogue.
  - The file is redirected into awk, not passed as an operand, so a relative name such as `cue=1.srt` is never parsed as an awk assignment. This preserves sed's behavior.
  - An unterminated final line is now printed with an LF; sed preserved the missing newline.
  - A missing file exits 1 with bash's diagnostic, where it previously exited with sed's status.
- **Accepted limitations:** a dialogue line whose whole text has the timing shape is dropped. Shell scripts are not measured by coverage.py, so the subprocess tests and the mutation evidence protect them instead.

## Change

- [extract_subtitle_text.sh](../extract_subtitle_text.sh) replaces the `sed` pipeline with a commented awk program implementing the rules above.
- [test_extract_subtitle_text.py](../tests/tooling/test_extract_subtitle_text.py) adds 7 tests (12 cases). They run the script with `bash` in fresh subprocesses, each with an explicit minimal environment (`PATH=os.defpath`, plus `HOME` and `TMPDIR` under `tmp_path`), `LC_ALL=C.UTF-8`, `cwd=tmp_path` and an empty stdin. All inputs are synthetic files under `tmp_path`.

README's description ("to strip SRT timestamps") remains accurate and is unchanged.

## Mutation evidence

The implementation agent produced the evidence. Each mutant was applied in a disposable copy of the candidate, which was then deleted. Every run used `PYTHONPATH`, `TMPDIR` and `--basetemp` inside that copy. A hook added only to the copy's conftest checked that `SCRIPT` resolved to the copy's script; every run printed the same provenance line. The command was `python -m pytest tests/tooling/test_extract_subtitle_text.py --no-cov -p no:cacheprovider -rf`. The unmutated baseline (seed 2452961338) and the restored run (seed 631205097) each passed 12 tests.

| Mutant | Protected invariant | Seed | Result |
|---|---|---|---|
| Remove the CR strip | CRLF output equals LF output, with no CR | 1055023216 | 4 failed, including `test_crlf_input_matches_lf_output` |
| Treat every digits-only line as an index | Numeric dialogue survives | 326799215 | 4 failed; `2026`, `42`, `7` and `8` were lost |
| Remove the BOM strip | A BOM-prefixed first index is removed | 1853211617 | 2 failed; output was `b'\xef\xbb\xbf1\nHello\n'` |
| Drop the EOF flush of a held line | A final digits-only line is kept | 575770951 | 2 failed; output was `b'First\n'` instead of `b'First\n2026\n'` |
| Timing detection becomes `/-->/` | Dialogue containing `-->` is kept | 1191615140 | 2 failed; `A --> B` and `1 --> 2` were lost |
| Accept only `,` before milliseconds | Period-millisecond timings and their index are removed | 615690365 | 2 failed |
| Pass the file as an awk operand | A name such as `cue=1.srt` is read as the file | 1842695359 | 1 failed; empty output |

Every mutant was killed.

## Review

The Codex reviewer ran in session `01a1302f-ca2f-76a0-8ed0-cb9b1a1dffa1`. Its model was `gpt-6.1-sol` with reasoning effort `high`, taken from the dispatch command because the reviewer cannot observe them itself. The review was a full first assessment of the frozen candidate.

- **Gates and evidence:** the reviewer accepted the supplied gates. It reconstructed all seven mutants and matched their hashes, seeds, provenance and failures, so it did not replay them.
- **Focused run:** it ran the tests in scratch (12 passed, seed 212026), with checks on child-process arguments and working directories.
- **Boundary probes:** it ran 16 probes, all matching the contract. They covered:
  - empty or BOM-only input, and blank input;
  - zero-padded numbers, and numbers held before a blank line, an invalid timing line or another number;
  - whitespace preservation, a later BOM, and an unterminated timing line at EOF;
  - Unicode and quoted file names, a directory argument, and an unreadable file.
- **Verdict:** no Blocking findings, no Non-blocking findings and no Nits.
- **Integrity:** the main agent's snapshot after the review matched the frozen pre-review snapshot exactly.

## Limitations and cleanup

Portability was exercised only under mawk 1.3.4; gawk and busybox awk are not installed in the devcontainer. The implementation clone and the mutation and review scratch copies were deleted. Unrelated untracked files were preserved.
