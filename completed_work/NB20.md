# NB20 — Invalid coverage thresholds disable per-file comparisons

## Origin

A 2026-09 assessment ([historical assessments](history.md#evidence-provenance)) classified NB20 as Non-blocking with Low severity, and validated it with an extracted coverage parser fed synthetic reports. [check-coverage.sh](../check-coverage.sh) accepted non-finite and out-of-range floats for `COVERAGE_THRESHOLD`. A report at 1% coverage failed with threshold `80` but passed with `nan` or `-1`. pytest's aggregate `--cov-fail-under` still applied, but the separate per-file and branch checks were bypassed whenever the aggregate passed.

Acceptance required that NaN, infinities, negative values and values above 100 fail clearly, while valid boundaries and ordinary thresholds behave as documented. [D4](../DESIGN.md#d4) and the existing gate policy had to be preserved.

NB20 was executed with [NB21](NB21.md) and [N2](N2.md) as a shell-helper group. Each task was committed and reviewed separately.

## Boundary

- **Intent:** validate the threshold before pytest runs, so a nonsensical value cannot silently disable the per-file gate.
- **Direction:**
  - A short `python3` check requires the threshold to parse as a float and satisfy `0 <= t <= 100`. That chained comparison is false for NaN and for both infinities.
  - On failure the script prints a `check-coverage:` message to stderr and exits non-zero without running pytest.
  - An empty or unset value keeps the default of 80.
- **Compatibility surface:** the gate script's CLI and environment. Preserved:
  - argument forwarding to pytest and the default threshold;
  - the failure when pytest writes no coverage report;
  - pytest's exit status taking precedence;
  - the existing success and failure messages and the comparison logic.
- **Non-goals:** pytest's configured aggregate floor, the comparison semantics and the report format.
- **Assumptions accepted by the main agent:**
  - An invalid threshold exits with status 1.
  - `float()` decides what parses, so `' 80 '` and `1_0` are accepted. This matches the existing comparison step.
  - The message shows the raw value with `repr`.

## Change

- [check-coverage.sh](../check-coverage.sh) validates the threshold before `mktemp` and pytest. Its header comment documents the inclusive range, the default and the fail-before-pytest behavior.
- [README.md](../README.md#testing) states the accepted range and that an invalid value fails before pytest runs.
- [test_check_coverage.py](../tests/tooling/test_check_coverage.py) adds 26 cases. Each runs the script with `bash` in a fresh subprocess:
  - **Stub:** an owned stub executable named `pytest` comes first on `PATH`. It records its arguments, copies a synthetic coverage.py JSON report to the `--cov-report=json:<path>` destination and exits with a chosen status, so the real suite never runs.
  - **Environment:** built from scratch. `PATH` holds the stub directory, the interpreter directory, `/usr/bin` and `/bin`; `HOME` and `TMPDIR` sit under `tmp_path`; `LC_ALL=C.UTF-8`. `cwd` is `tmp_path`. Each run also asserts that the owned `TMPDIR` is empty afterwards.
  - **Invalid values:** each of `nan`, `NaN`, `inf`, `-inf`, `infinity`, `-1`, `-0.5`, `100.1`, `1e3`, `eighty` and `80%` fails with the message and never invokes the stub.
  - **Boundaries:** `0` and `100` are accepted and still applied.
  - **Existing behavior:** report-path and argument forwarding, the missing-report failure, and pytest's exit-status precedence.
  - **Default threshold:** unset, empty and explicit `80` all pass a report at or above 80, and all fail a file below 80 on statements or branches while the total passes.

## Mutation evidence

- **Producer:** the implementation agent.
- **Setup:** disposable copy (deleted afterwards), seed `20261012`, with `PYTHONPATH`, `TMPDIR` and `--basetemp` inside the copy. A scratch-only conftest hook required the test file and `SCRIPT` to lie inside the copy; every run printed `ACTUAL_SCRIPT_PROVENANCE`.
- **Baseline:** the unmutated copy passed 26.

| Mutant | Protected property | Result |
|---|---|---|
| `not 0 <= t <= 100` → `t < 0 or t > 100` | NaN and unparsable values are rejected | Killed: 4 failed (`nan`, `NaN`, `eighty`, `80%`) |
| Lower bound removed | Negative values are rejected | Killed: 3 failed |
| Upper bound removed | Values above 100 and infinity are rejected | Killed: 4 failed |
| Exclusive bounds `0 < t < 100` | 0 and 100 are accepted | Killed: 3 failed |
| Validation moved after pytest | Validation runs before pytest | Killed: 11 failed |
| `\|\| exit 1` dropped | A failed validation stops the script | Killed: 11 failed |
| `${COVERAGE_THRESHOLD:-80}` → `${COVERAGE_THRESHOLD-80}` | An empty value keeps 80 | Killed: 3 failed |
