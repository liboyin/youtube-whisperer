# NB34 — Staged-file publication is hand-copied in three places

## Origin

A Claude Opus 5.5 re-review of `5fdb927`, confirmed by a main-agent source comparison at `a424a2b` on 2026-10-11, raised this while reviewing [NB8](NB8.md). There it was deferred as a Non-blocking, Low-severity structural observation and proposed simplification, because it needed a three-module refactor outside that boundary.

Three functions each repeated the same steps:

- [video download](../youtube_whisperer/downloaders/video_downloader.py) (`download_video`)
- [SRT publication](../youtube_whisperer/adaptors/srt_deduplicator.py) (`publish_srt_text`)
- [WAV conversion](../youtube_whisperer/transcriber/waveform_loader.py) (`save_as_wav_file`)

The repeated steps were target resolution, mode capture, `chmod`, `os.link` create-if-absent for `NEVER`/`RENAME` with the file-collision rule, and atomic replacement otherwise. A future fix to this data-loss-sensitive protocol could reach one copy and miss the others.

TODO's acceptance required:

- the existing video, SRT and WAV publication tests pass unchanged;
- mutation evidence shows the helper's collision, mode and replacement rules are protected through every caller.

## Revalidation

At `9b11a58` all three copies were present. The WAV copy expressed the collision branch as `if not target.is_file(): raise` and fell through to `return output_file_path`, while the other two returned early. These are equivalent because only `finally` cleanup follows publication.

Two constraints came from the tests. The tests inject faults by patching `os.link`, `os.replace` (video) and `Path.replace` (SRT/WAV) through the module objects. Python 3.12.3's `Path.replace` calls `os.replace` at runtime, so one helper that calls `stage.replace(target)` honors both patch styles.

## Boundary

- **Intent:** one helper owns the shared publication steps of the [completion contract](../DESIGN.md#srt-as-the-output-format) and [D22](../DESIGN.md#d22). The change preserves behavior.
- **Direction:** a new module, [publication.py](../youtube_whisperer/publication.py), with two functions:
  - `resolve_publication_target(path)` resolves through symlinks, prepares the resolved target and captures its permission bits (`None` when absent).
  - `publish_staged_file(stage, target, mode, overwrite)` applies the mode, then hard-links create-if-absent for `NEVER`/`RENAME` (accepting only a file collision) and otherwise calls `stage.replace(target)`.
  - Each caller keeps its own stage creation, ownership tracking, cleanup, ordering and docstring contracts.
- **Compatibility surface ([D18](../DESIGN.md#d18)):** all preserved. That covers the signatures, return values, exceptions, side effects and ordering of `download_video`, `download_video_with_default_title`, `publish_srt_text`, `save_segments_as_srt`, `deduplicate_srt_file` and `save_as_wav_file`.
  - Only now-unused incidental `os`/`stat` module imports were dropped from the callers.
  - No HTTP or CLI behavior changes.
  - The two new functions are public under D18 from this commit.
- **Non-goals:**
  - stage naming, creation or cleanup;
  - the WAV ffmpeg lifecycle and the SRT write path;
  - overwrite preflight and prompts;
  - [B5](B5.md) naming;
  - any change to D22, durability or stale-stage scavenging.
- **Assumptions and deviations accepted by the main agent:**
  - **A1 — placement.** A new root-level module rather than `utils.py`. `utils.py` imports `redis` and `config`, which would add Redis to the downloader, adaptor and transcriber import paths. Root-level single-purpose modules (`domain.py`, `task_preparation.py`) already exist.
  - **A2 — test references.** With `os` no longer imported by `srt_deduplicator` and `waveform_loader`, seven test lines changed from `patch.object(testee.os, ...)` to `patch.object(os, ...)`. One line in `test_youtube_worker.py` (D2 below) changed the same way. `testee.os` was the global `os` module, so each patch is unchanged in effect, and no case, assertion or parametrization changed. This is the only departure from "tests pass unchanged". The rejected alternative was keeping a dead `import os  # noqa: F401` solely for tests.
  - **D1 — helper argument.** `resolve_publication_target` takes a path the caller has already prepared, so each caller still calls `prepare_output_file` itself. `test_download_video_returns_early_when_existing_file_should_not_be_overwritten` patches `video_downloader.prepare_output_file`, and the call order of every check is unchanged.
  - **D2 — missed reference.** `tests/workers/test_youtube_worker.py` imported `srt_deduplicator` only to patch `os.link` through it. It now imports `youtube_whisperer.publication` for the same global patch.

## Change

- **New module:** [publication.py](../youtube_whisperer/publication.py) holds the two helpers with Google-style docstrings.
- **Callers:** the three callers delegate to the helpers and no longer contain any mode, link or replace logic. The video expandvars check still runs after target resolution and before `mkdtemp`.
- **DESIGN:** [DESIGN](../DESIGN.md#srt-as-the-output-format) states that `publication.py` owns the shared steps, while each caller owns stage creation and cleanup.
- **Tests:** only the A2/D2 reference changes above.

## Review

- **Reviewer:** a new Codex CLI session, `01a13550-9595-7b52-a2c7-c1d1250f84fd`, made a full first assessment of the frozen candidate. Its model, `gpt-6.1-sol`, and reasoning effort, `high`, come from the dispatch command.

- **Focused run:** the four caller/integration test files plus scratch-only source-path probes gave 211 passed (seed 340913), with actual-import provenance verified.
- **Verdict:** no Blocking findings.
- **Integrity:** the main agent's post-review snapshot matched the pre-dispatch snapshot exactly.
- **Nit:** the `publish_staged_file` docstring said the stage is never removed, but successful replacement consumes the stage pathname. Validated: `stage.replace(target)` renames the stage, and the reviewer's probes confirmed this for `ALWAYS` and `PROMPT`. Fixed: the docstring now says replacement consumes the stage pathname and callers clean up any owned stage left behind.
- **D1 wording:** the reviewer noted that WAV prepares its literal path and resolved target once each, as it did at the starting revision. An early working-record note claiming WAV went from two literal preparations to one was therefore wrong; this record omits it.
