# NB31 — Compose repeats the shared application-service configuration

**Priority:** Non-blocking, Low.

**Evidence:** a validated structural observation from the source inventory at `ed9b3a1` on 2026-09-14. The task proposes a simplification. Lines 25 to 83 of the [CPU Compose file](../../docker-compose.cpu.yaml) repeat the build, init, restart, volume, environment, env-file and Redis-health settings across four application services. The existing anchors cover the build and the volumes separately, but the common service block stays repeated.

**Revalidation, 2026-11-23:** D10 is superseded by D54 (devcontainer isolation). The devcontainer's Compose layer now replaces each service's mounts with `!override`. A shared extension mapping must keep those replacements working.

- **Outcome:** one local extension mapping supplies the common defaults of the application services. Service names, entrypoints, ports and GPU overrides stay explicit.
- **Acceptance:** the expanded CPU and GPU configurations match the originals. Render them with synthetic environment values and synthetic env files only. Preserve every service, volume, health condition and override.
- **Dependencies:** the devcontainer still starts the workers, as [D54](../../DESIGN.md#d54) records.
- **Non-goals:** keep Redis separate. Add no generated configuration, no further Compose file and no change to the sharing of resources.
