# T1 — Isolate the devcontainer and mirror youtube-collector's setup

**Outcome:** Implemented ([D54](../../DESIGN.md#d54)–[D57](../../DESIGN.md#d57)): the default devcontainer uses development-only storage in its own Compose project, and an opt-in REAL DATA configuration mounts the real library. No SSH keys are mounted. Agent state and the shared `agent-workflow-common` checkout persist on `dev_persist`.

## Origin

An ad-hoc change requested by the user on 2026-11-22. The user is unifying the structure of their Python projects on youtube-collector's, starting with this repository, and accepted a plan of four changes. This record covers the first, the devcontainer. The user chose to mirror collector's host-data isolation ([D54](../../DESIGN.md#d54)), SSH agent forwarding ([D55](../../DESIGN.md#d55)), persistent agent state with the shared tool checkout ([D56](../../DESIGN.md#d56)), and `T` IDs for new records ([D57](../../DESIGN.md#d57)). The user authorized doing this change from the WSL host, outside the devcontainer, with Docker available for host checks.

## Boundary

- **Intent:**
  - The default devcontainer never mounts host data: every service gets development-only storage, and the devcontainer has its own Compose project, no fixed container names and no published port.
  - An opt-in REAL DATA configuration brings the real media library, model cache and a read-only profile back, and requires `ASSETS_DIR`.
  - No SSH keys are mounted. The creation hook records GitHub's host keys.
  - Claude Code and Codex state persists on a `dev_persist` volume, and the hook provisions the unpinned `agent-workflow-common` checkout at `/workspaces/agent-workflow-common`.
- **Dependencies:** youtube-collector's implementation of its decisions C28, C31 and C61, which this change copies. Compose 2.24.4 or later for `!override` and `!reset`.
- **Compatibility surface:**
  - Production `docker compose up`, GPU and CPU, renders identically: same services, mounts, container names, port and the directory-named project. Its Redis queue and volumes are therefore untouched.
  - The image gains two empty, runtime-user-owned mount points (`assets/`, `~/.whisper`) and, in `dev` only, `~/persist`. A production bind mount hides them. A new named volume now initializes writable instead of root-owned.
  - The default devcontainer no longer processes real media. The workers still start, against the development queue and storage.
  - No Python API, HTTP or CLI behavior changes.
- **Non-goals:**
  - The shared review tools, the governance restructure and the task layout, which are the plan's later changes.
  - Pinning `agent-workflow-common`, or updating it automatically.
  - Changing the base images, the production mounts or `common-utils:latest`.
- **Validation:** Compose renders on the host for production, the default devcontainer and REAL DATA. A dev image build. The gates on a HEAD baseline and on the candidate. Static tests of the storage invariant and the ported setup tests, with mutation evidence for the isolation invariant.
- **Done:** gates pass; the isolation renders and tests hold; the review has no Blocking finding; the user rebuilds the devcontainer.

## Change

- **`.devcontainer/docker-compose.devcontainer.yaml`:** names the project `youtube-whisperer-dev`. Replaces each service's mounts with `!override`: `dev_assets` and `dev_models` for the API container and the workers, `dev_persist` for the API container, and `dev_redis` for Redis. Resets the API container's port and both fixed container names, sets the API container's restart policy to `no`, and sets `CLAUDE_CONFIG_DIR` and `CODEX_HOME`.
- **`.devcontainer/real-data/`:** a second `devcontainer.json`, identical except for its name and Compose list, and a layer that mounts `${ASSETS_DIR:?…}`, `${WHISPER_MODELS_VOLUME:-dev_models}` and a read-only `${FIREFOX_PROFILE_DIR:-dev_firefox_profile}` in the four application services, and sets `WHISPERER_REAL_DATA=1`.
- **`.devcontainer/devcontainer.json`:** a name, and no `~/.ssh` mount.
- **`.devcontainer/postCreateCommand.sh`:** creates the persistent state directories, runs `setup-github-ssh.sh`, changes only `/workspaces` ownership, and runs `setup-agent-tools.sh` before the CLI installers. It no longer runs `codex --version` at the end. It is byte-identical to collector's hook at `5a95c4d`.
- **`.devcontainer/setup-github-ssh.sh`:** writes `~/.ssh/known_hosts` from `api.github.com/meta`. It is collector's helper from `9e3276c` (its T62), citing D55 instead of C31.
- **`.devcontainer/setup-agent-tools.sh`:** copied unchanged from youtube-collector.
- **`Dockerfile`:** creates the media library and model-cache mount points at the end of `runtime`, after the dependency layers, and `~/persist` in `dev`.
- **Tests:** `tests/tooling/test_setup_agent_tools.py`, copied unchanged from youtube-collector at `5a95c4d`, and the new `tests/tooling/test_devcontainer_storage.py`, which reads the Compose files with a loader that keeps the merge tags. PyYAML joins the `dev` group, where it was already locked as a transitive dependency, so the lock gains only the group entries.
- **Docs:** README (the Dev Container section, the `.env` preparation note and the host-path variables) and DESIGN (the new Development container section with D54 to D56, D57, the structure listing, and D10 marked as superseded).
